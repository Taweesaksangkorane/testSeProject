# รายงานทดสอบการสกัดข้อมูล RS-1

> สถานะ: มีการทดสอบแบบอัตโนมัติ 63 กรณีผ่านทั้งหมด (15 พฤศจิกายน 2569) ด้วยข้อมูลสังเคราะห์ และได้บันทึกผลทดสอบเอกสารจริงจาก stakeholder หนึ่งไฟล์แบบไม่จัดเก็บไฟล์ไว้ในรีโป จึง **ยังไม่รายงานเปอร์เซ็นต์ความถูกต้องของเอกสารจริงทั้งชุด** หรือจำนวนข้อผิดพลาดที่เกิดจริง

## ขอบเขตการทดสอบ

การทดสอบครอบคลุมตัวสกัดข้อมูลจากแบบฟอร์ม RS-1 ที่อัปโหลดเป็น `.docx` ไปยัง JSON และหน้าตรวจทาน โดยใช้ 23 หัวข้อบนหน้าจอเป็นขอบเขตการรายงานผล รายการและสถานะของแต่ละหัวข้อแสดงในส่วนผลเอกสารจริงด้านล่าง

## วิธีเทียบผล

### ข้อมูลสังเคราะห์

1. สร้างข้อมูลหรือแบบฟอร์มทดสอบและกำหนดผลที่คาดหวังสำหรับแต่ละกรณี
2. สกัดข้อมูลจากไฟล์ทดสอบ แล้วเปรียบเทียบผลกับค่าที่คาดหวังตามชนิดข้อมูล เช่น ข้อความ ตัวเลือก ตาราง และตัวเลข
3. บันทึกผลผ่านหรือไม่ผ่านและรายละเอียดความแตกต่างของแต่ละกรณี แล้วสรุปตามประเภท กรณี E01–E50 ระบุไว้ด้านล่าง แต่รายงานนี้ยังไม่ได้บันทึกผลผ่านหรือไม่ผ่านแยกรายกรณี

### เอกสารจริง

1. เปิดเอกสารต้นฉบับและผลสกัดบนหน้าตรวจทาน ตรวจสถานะทั้ง 23 หัวข้อตามรายการด้านล่าง
2. เมื่อหน้าจอแสดง `ไม่พบข้อมูล` ให้ตรวจต้นฉบับว่าไม่มีข้อมูลจริงหรือระบบสกัดไม่พบ; หากไม่มีข้อมูลในต้นฉบับ ไม่นับเป็นข้อผิดพลาดในการสกัด
3. เมื่อแสดง `กรุณาตรวจสอบ` ให้ดูข้อมูลต้นฉบับและระบุส่วนที่สกัดได้หรือยังไม่ได้ รวมถึงสาเหตุที่สังเกตได้
4. บันทึกผลเป็นรายหัวข้อ โดยแยกสถานะบนหน้าจอออกจากผลเทียบความถูกต้องของเนื้อหา สถานะ `สกัดแล้ว` เพียงอย่างเดียวไม่ยืนยันว่าทุกค่าถูกต้อง

สำหรับเอกสารจริงหนึ่งไฟล์ที่รายงานนี้บันทึก ผู้ทดสอบตรวจแล้วว่าทั้งสองหัวข้อที่ไม่พบข้อมูลไม่มีอยู่ในต้นฉบับ และพบว่าตารางแผนงานรูปแบบต่างจากเทมเพลตยังเติมลงฟอร์มไม่ได้ ส่วนผลเทียบเนื้อหาทีละค่ายังไม่ได้บันทึกครบ จึงรายงานได้เฉพาะสัดส่วนสถานะบนหน้าจอ ไม่ใช่เปอร์เซ็นต์ความถูกต้องรายค่า

คำสั่งทดสอบ regression ของรีโป:

```powershell
Set-Location prototype/rs1-extraction
npm.cmd test
```

## ผลทดสอบข้อมูลสังเคราะห์

ข้อมูลสังเคราะห์ใช้ยืนยันว่ากฎการสกัดทำงานในกรณีที่ออกแบบไว้ โดยผล regression ปัจจุบันผ่าน 63 กรณี และไม่พบกรณีล้มเหลว

| กลุ่มทดสอบ | ผลที่ยืนยันจากข้อมูลสังเคราะห์ |
| --- | --- |
| หัวข้อและเนื้อหา | จัดหัวข้อไทย/อังกฤษ, หัวข้อสลับลำดับ, หัวข้อเปลี่ยนเลข, คำพ้อง และการพิมพ์คลาดเคลื่อนเล็กน้อยได้ |
| ข้อมูลบุคคลและความร่วมมือ | แยกข้อมูลที่มีป้ายกำกับ, ข้อมูลข้ามบรรทัด และข้อความความร่วมมือได้ |
| Checkbox | ครอบคลุม Unicode, Wingdings, Word content control และ legacy form field |
| แผนงาน | ครอบคลุมตารางกิจกรรม/ระยะเวลา 2 คอลัมน์, ลำดับคอลัมน์กลับกัน, ตาราง Gantt และ merged cell |
| งบประมาณ | ครอบคลุมตาราง 2 คอลัมน์, คอลัมน์จำนวน/ตัวคูณ, จำนวนเงินที่เว้นว่าง และแถวว่าง |
| หลักฐานต้นทาง | คงลำดับย่อหน้า ตาราง, checkbox และข้อมูลโครงสร้างตารางสำหรับตรวจทาน |

ผลชุดนี้ยืนยันเฉพาะพฤติกรรมในกรณีจำลอง ไม่ใช่ความแม่นยำกับเอกสารจริง และไม่รวมกับผลการทดสอบเอกสารจริงด้านล่าง

## ผลรายหัวข้อจากเอกสารจริงของ stakeholder

ทดสอบเอกสาร DOCX จริงที่ stakeholder อนุญาตให้นำมาใช้ตรวจการสกัด โดยไม่คัดลอกไฟล์ เนื้อหา หรือข้อมูลระบุตัวตนลงใน Git ผลที่ยืนยันได้มีดังนี้

สำหรับเอกสารจริงไฟล์ล่าสุด ผู้ทดสอบยืนยันว่าข้อมูลส่วนใหญ่แสดงผลได้; ส่วน ก ข้อ 12 ต้องตรวจสอบ และไม่พบข้อมูลในส่วน ก ข้อ 3 และ 15 ตามตารางผลด้านล่าง

การตรวจหน้าจอครบทุกหัวข้อตามเทมเพลตแสดงสถานะ 23 หัวข้อ: `สกัดแล้ว` 20 หัวข้อ, `กรุณาตรวจสอบ` 1 หัวข้อ (ส่วน ก ข้อ 12), และ `ไม่พบข้อมูล` 2 หัวข้อ (ส่วน ก ข้อ 3 และ 15) ผู้ทดสอบตรวจต้นฉบับแล้วว่าข้อมูลที่ไม่พบทั้งสองหัวข้อไม่มีอยู่ในเอกสาร จึงไม่นับเป็นข้อผิดพลาดในการสกัด สถานะ `สกัดแล้ว` หมายถึงระบบพบข้อมูลสำหรับแสดงผล; การยืนยันความถูกต้องของเนื้อหาต้องเทียบกับเอกสารต้นฉบับ

สัดส่วนสถานะบนหน้าจอสำหรับเอกสารจริง **หนึ่งไฟล์** คำนวณจากจำนวนหัวข้อในแต่ละสถานะหารด้วย 23 หัวข้อทั้งหมด:

| --- | ---: | ---: |

ข้อสรุปจาก stakeholder คือให้ความสำคัญกับการเก็บข้อมูลมากกว่าการบังคับให้ตารางตรงเทมเพลต RS-1 ดังนั้นเกณฑ์ยอมรับต้องวัดว่าระบบดึงกิจกรรม ช่วงเวลา และข้อมูลตารางได้ แม้โครงสร้างตารางต่างจากเทมเพลต; เมื่อยังสกัดไม่ได้ ต้องเก็บตารางต้นฉบับและระบุเป็นข้อผิดพลาดสำหรับแก้ไขภายหลัง ไม่ควรบันทึกว่าไม่มีข้อมูล

รายการ E01–E50 เป็นกรณีที่ทดสอบด้วยข้อมูลหรือแบบฟอร์มที่สร้างขึ้นเอง แยกตามประเภท จำนวน 50 รายการไม่ได้หมายความว่าพบข้อผิดพลาด 50 จุด ตารางนี้ระบุขอบเขตการทดสอบ; ผลผ่านหรือไม่ผ่านรายรายการต้องอ้างอิงหลักฐานการทดสอบแต่ละกรณี และไม่รวมกับผลเอกสารจริง จำนวน 63 กรณี regression ข้างต้นเป็นจำนวนการทดสอบอัตโนมัติ จึงไม่ควรนำมาบวกกับ 50 รายการโดยไม่ตรวจสอบความซ้ำซ้อน

## ข้อจำกัด

- รองรับเฉพาะไฟล์ **DOCX** ขนาดไม่เกิน 10 MB ในเส้นทางอัปโหลดปัจจุบัน
- ไม่รองรับ `.doc`, PDF, ภาพสแกน หรือ OCR; ต้องแปลงเป็น DOCX ที่มีข้อความก่อน
- ข้อมูลส่วนใหญ่ใน regression test เป็นข้อมูลสังเคราะห์ที่กรอกขึ้นเอง; การตรวจเอกสารจริงหนึ่งไฟล์เป็นหลักฐานเฉพาะกรณี ไม่ทดแทนการเทียบกับเอกสารจริงหลายรูปแบบ และเอกสารที่มีรูปแบบต่างจาก RS-1 อาจได้สถานะ `review` หรือ `missing`
- เอกสารจริงและ JSON ที่มีข้อมูลส่วนบุคคลไม่ควรถูก commit; เก็บ fixture ที่ลบข้อมูลระบุตัวตนแล้วพร้อมเฉลยแยกต่างหาก
