# Use Case Specification

## ระบบบริหารจัดการทุนวิจัยส่วนตัว มหาวิทยาลัยแม่ฟ้าหลวง

เอกสารนี้อธิบายพฤติกรรมหลักของระบบตาม Requirements, State Transition Diagram และ Workflow ล่าสุด โดย e-Office เป็นกระบวนการภายนอก Web และไม่มีการเชื่อมต่อผ่าน API

## 1. บทบาทผู้ใช้

| บทบาท | ความรับผิดชอบในระบบ |
|---|---|
| นักวิจัย | จัดทำและยื่นข้อเสนอ ติดตามสถานะ ยื่นเอกสารปิดโครงการ และส่งรายงานฉบับแก้ไข |
| เจ้าหน้าที่ส่วนบริหารงานวิจัย | ตรวจเอกสาร บันทึกผลตรวจ/รับรอง บันทึกขยายเวลา จัดการเอกสารปิด และบันทึกปิดโครงการ |
| ผู้ทรงคุณวุฒิ | เข้าถึงรายงานที่ได้รับมอบหมายและส่งผลประเมินหนึ่งรอบ |

## 2. กติกาทั่วไป

- นักวิจัยเข้าถึงได้เฉพาะโครงการของตนเอง
- เจ้าหน้าที่เข้าถึงโครงการตามสิทธิ์ที่ได้รับ
- ผู้ทรงคุณวุฒิเห็นเฉพาะงานประเมินที่ได้รับมอบหมาย
- การอัปโหลดไฟล์หรือบันทึกร่างเพียงอย่างเดียวไม่ทำให้สถานะเปลี่ยน เว้นแต่ผู้ใช้กดยืนยันในขั้นตอนที่กำหนด
- ระบบบันทึกผู้ดำเนินการ วันเวลา และรายละเอียดเหตุการณ์สำคัญ

## 3. รายละเอียด Use Case

### 3.1 สร้างและบันทึกร่างโครงการ

| รายการ | รายละเอียด |
|---|---|
| ผู้ดำเนินการหลัก | นักวิจัย |
| เงื่อนไขก่อนเริ่ม | นักวิจัยเข้าสู่ระบบแล้ว |
| จุดเริ่มต้น | นักวิจัยเลือกสร้างโครงการใหม่ |
| ขั้นตอนหลัก | 1.ระบบแสดงแบบฟอร์ม RS-1 ตามฟิลด์ที่ระบบรองรับ<br>2. นักวิจัยกรอกข้อมูล<br>3. นักวิจัยกดบันทึกร่าง<br>4. ระบบสร้างระเบียนโครงการและบันทึกข้อมูล |
| กรณีทางเลือก | นักวิจัยสามารถกลับมาแก้ไขและบันทึกร่างซ้ำได้ |
| ผลลัพธ์ | โครงการมีสถานะ `DRAFT` และมีประวัติการบันทึก |

### 3.2 อัปโหลดและสกัดข้อมูล RS-1

| รายการ | รายละเอียด |
|---|---|
| ผู้ดำเนินการหลัก | นักวิจัย |
| เงื่อนไขก่อนเริ่ม | โครงการอยู่ในสถานะ `DRAFT` |
| จุดเริ่มต้น | นักวิจัยเลือกอัปโหลดเอกสาร RS-1 |
| ขั้นตอนหลัก | 1. นักวิจัยเลือกไฟล์ RS-1<br>2. ระบบตรวจชนิดและความสมบูรณ์ของไฟล์<br>3. ระบบสกัดข้อมูลที่รองรับ<br>4. ระบบแสดงข้อมูลที่พบและข้อมูลที่ไม่พบ<br>5. นักวิจัยตรวจสอบ แก้ไข และบันทึกข้อมูล |
| กรณีทางเลือก | หากไฟล์ไม่รองรับหรือเสียหาย ระบบแจ้งเหตุผลและไม่บันทึกข้อมูลที่ไม่ถูกต้อง |
| ผลลัพธ์ | ข้อมูลที่นักวิจัยยืนยันถูกเก็บในร่างโครงการ โดยสถานะยังเป็น `DRAFT` |

### 3.3 จัดทำ PDF ฉบับพร้อมยื่นต้นสังกัด

| รายการ | รายละเอียด |
|---|---|
| ผู้ดำเนินการหลัก | นักวิจัย |
| เงื่อนไขก่อนเริ่ม | ข้อมูล RS-1 ที่จำเป็นครบตามกติกาของระบบ |
| จุดเริ่มต้น | นักวิจัยยืนยันจัดทำ PDF ฉบับพร้อมยื่น |
| ขั้นตอนหลัก | 1. ระบบตรวจข้อมูลที่จำเป็น<br>2. ระบบสร้าง PDF จากข้อมูลล่าสุด<br>3. นักวิจัยยืนยันว่าเป็นฉบับพร้อมยื่น<br>4. ระบบเปลี่ยนสถานะเป็น `AFFILIATION_REVIEW` |
| กรณีทางเลือก | การดู Preview หรือดาวน์โหลด PDF โดยไม่ยืนยันฉบับพร้อมยื่น จะไม่เปลี่ยนสถานะ |
| ผลลัพธ์ | โครงการรอการพิจารณาจากต้นสังกัดภายนอก Web |

### 3.4 แก้ไขข้อเสนอตามความเห็นต้นสังกัด

| รายการ | รายละเอียด |
|---|---|
| ผู้ดำเนินการหลัก | นักวิจัย |
| เงื่อนไขก่อนเริ่ม | โครงการอยู่ในสถานะ `AFFILIATION_REVIEW` |
| จุดเริ่มต้น | ต้นสังกัดแจ้งให้แก้ไขข้อเสนอผ่านกระบวนการภายนอก Web |
| ขั้นตอนหลัก | 1. นักวิจัยแก้ไขข้อมูลหรือเอกสารข้อเสนอ<br>2. จัดทำ PDF ฉบับใหม่<br>3. นำเสนอให้ต้นสังกัดพิจารณาซ้ำภายนอก Web |
| ผลลัพธ์ | สถานะหลักยังเป็น `AFFILIATION_REVIEW` |

### 3.5 ยืนยันส่งข้อเสนอให้เจ้าหน้าที่

| รายการ | รายละเอียด |
|---|---|
| ผู้ดำเนินการหลัก | นักวิจัย |
| เงื่อนไขก่อนเริ่ม | โครงการอยู่ในสถานะ `AFFILIATION_REVIEW` และต้นสังกัดเห็นชอบแล้ว |
| จุดเริ่มต้น | นักวิจัยกดปุ่มยืนยันส่งข้อเสนอ |
| ขั้นตอนหลัก | 1. นักวิจัยแนบ RS-1 ฉบับลงนามครบ<br>2. แนบรายงานประชุมหรือเอกสารยืนยันความเห็นชอบของต้นสังกัด<br>3. หากใช้ลายเซ็นอิเล็กทรอนิกส์ของผู้อื่น นักวิจัยยืนยันว่าได้รับความยินยอมแล้ว<br>4. ระบบตรวจความครบถ้วน<br>5. นักวิจัยกดยืนยันส่ง<br>6. ระบบเปลี่ยนสถานะเป็น `STAFF_REVIEW` |
| กรณีทางเลือก | หากเอกสารหรือคำยืนยันไม่ครบ ระบบแสดงรายการที่ขาดและไม่ยอมให้ส่ง |
| ผลลัพธ์ | เจ้าหน้าที่เห็นข้อเสนอในรายการรอตรวจ |

| รายการ | รายละเอียด |
|---|---|
| ผู้ดำเนินการหลัก | เจ้าหน้าที่ส่วนบริหารงานวิจัย |
| เงื่อนไขก่อนเริ่ม | โครงการอยู่ในสถานะ `STAFF_REVIEW` และเอกสารถูกต้อง |

### 3.13 ประเมินรายงานวิจัย 5 บท

| รายการ | รายละเอียด |
|---|---|
| ผู้ดำเนินการหลัก | ผู้ทรงคุณวุฒิ |

| เงื่อนไขก่อนเริ่ม | เอกสารปิดเส้นทางรายงาน 5 บทผ่านการตรวจเบื้องต้น |
| จุดเริ่มต้น | เจ้าหน้าที่มอบหมายงานประเมินให้ผู้ทรงคุณวุฒิ |
| ขั้นตอนหลัก | 1. เจ้าหน้าที่ส่งร่างรายงานให้ผู้ทรงคุณวุฒิ<br>2. ระบบเปลี่ยนสถานะเป็น `REPORT_EVALUATION`<br>3. ผู้ทรงคุณวุฒิเข้าดูงานที่ได้รับมอบหมาย<br>4. เปิดอ่าน/ดาวน์โหลดร่างรายงาน<br>5. กรอก บันทึกร่าง หรือยืนยันส่งผลประเมินผ่าน Web<br>6. ระบบเก็บผลประเมิน วันเวลา และผู้ประเมิน<br>7. ระบบสร้าง PDF ผลประเมิน<br>8. เจ้าหน้าที่ส่งผลให้นักวิจัย |
| ผลลัพธ์ | การประเมินเสร็จสิ้นหนึ่งรอบ และไม่มีการส่งประเมินซ้ำ |

|---|---|
| ผู้ดำเนินการหลัก | นักวิจัย |
| ผู้เกี่ยวข้อง | เจ้าหน้าที่ส่วนบริหารงานวิจัย |
| เงื่อนไขก่อนเริ่ม | โครงการอยู่ในสถานะ `REPORT_EVALUATION`; นักวิจัยได้รับผลประเมินแล้ว |
| จุดเริ่มต้น | นักวิจัยส่งรายงานฉบับแก้ไขและเอกสารที่กำหนด |
| ขั้นตอนหลัก | 1. นักวิจัยแนบรายงานฉบับแก้ไข<br>2. เจ้าหน้าที่ตรวจความครบถ้วนของรายงานและเอกสาร<br>3. เจ้าหน้าที่บันทึกปิดโครงการ<br>4. ระบบเปลี่ยนสถานะเป็น `CLOSED`<br>5. เจ้าหน้าที่ดำเนินหนังสือแจ้งปิดผ่าน e-Office ภายนอก Web |
| กรณีทางเลือก | เอกสารไม่ครบ: เจ้าหน้าที่แจ้งให้นักวิจัยส่งเพิ่ม โดยยังไม่ปิดโครงการ |
| ผลลัพธ์ | โครงการปิดโดยไม่ส่งกลับให้ผู้ทรงคุณวุฒิประเมินซ้ำ |

## 4. ตารางความเชื่อมโยงกับสถานะ

| กระบวนการ | สถานะก่อน | สถานะหลัง |
|---|---|---|
| สร้างโครงการและบันทึกครั้งแรก | เริ่มต้น | `DRAFT` |
| ยืนยัน PDF ฉบับพร้อมยื่น | `DRAFT` | `AFFILIATION_REVIEW` |
| ยืนยันส่งข้อเสนอ | `AFFILIATION_REVIEW` | `STAFF_REVIEW` |
| เจ้าหน้าที่ตรวจผ่าน | `STAFF_REVIEW` | `COMMITTEE_ACKNOWLEDGEMENT` |
| เจ้าหน้าที่บันทึกรับรอง | `COMMITTEE_ACKNOWLEDGEMENT` | `IN_PROGRESS` |
| ยืนยันส่งเอกสารปิด | `IN_PROGRESS` | `CLOSURE_REVIEW` |
| เริ่มส่งรายงานให้ผู้ทรงคุณวุฒิ | `CLOSURE_REVIEW` | `REPORT_EVALUATION` |
| ปิดโครงการจากผลงานเผยแพร่ | `CLOSURE_REVIEW` | `CLOSED` |
| ปิดโครงการจากรายงานฉบับแก้ไข | `REPORT_EVALUATION` | `CLOSED` |
